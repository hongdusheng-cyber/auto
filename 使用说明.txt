可视化控制台
npm run ui
打开 http://localhost:17321
也可以直接运行：node scripts/control-panel.mjs

性能与运行管理
默认最多同时运行 8 个任务，浏览器保持打开的任务也计入上限。
需要调整时：CONTROL_PANEL_MAX_JOBS=2 node scripts/control-panel.mjs
达到上限会明确提示，请等待任务结束或点击“停止全部”后再启动。
已有共享登录态时，新浏览器槽位直接恢复登录态，不再复制整套浏览器资料；没有共享登录态时保留旧目录迁移方式。
停止任务时会等待子进程退出再释放浏览器槽位；初始化失败也会释放槽位。关闭控制台会停止它启动的任务。
日志按帧批量显示，网页保留最近最多 20 万字符、2000 段；服务端保留最近最多 512 Ki 字符、2000 段，重连快照还会按传输大小裁剪旧日志。
向上翻阅日志时不会被新日志强制拉回底部；连接中断时显示重连状态。
控制台请求体限制为 1 MB；代理参数总长度限制为 4096 字符，端口范围为 1–65535。

Mac 快速启动
双击 mac-control-panel.command
如果系统没有 node/npm，该文件会优先使用 Codex 桌面环境自带的 Node。

登录
脚本检测到管理员登录页时，会自动点击“使用 Logto 登录”，并在跳转后点击“登录”。
如果 Logto 要求填写账号、密码或完成验证，请在打开的浏览器中操作，脚本检测到登录成功后会自动继续。
首次成功登录后，登录态会同步保存到项目目录的 .playwright-auth-state.json；同时打开多个浏览器时，其他窗口会自动复用这份登录态，不再重复认证。
如果登录态过期，只需在任意一个窗口重新完成一次认证，其他正在等待的窗口会自动接续。
如需切换账号，可关闭运行中的浏览器后删除该文件，再重新运行任意任务完成认证。

添加账号
在“客户开通”卡片下方填写公司、姓名、邮箱，点击“添加账号”。
按公司完整名称进入该公司用户后台，再打开人事管理的用户列表并新建普通员工账号。
姓名可填写“张三”“欧阳明”，或按“姓 名”用空格分开；工作 Email 和个人 Email 使用同一个输入邮箱。
每次任务独立生成 10 位随机密码及正常格式的 11 位手机号，不发送短信。手机号重复时停止并在网页告警，不自动换号重试。
后台确认新建成功后，“添加账号”下方直接显示账号、密码和“复制账号 + 密码”按钮，最新成功结果显示在最上方。
结果区域不显示任务编号、手机号或失败记录；本次添加未完成时仅显示一句简短提示，详细错误保留在运行日志。
工作台服务运行期间，刷新页面可恢复服务端最近 50 个任务结果中的成功账号；重启服务后清空。
成功后关闭任务浏览器；失败时保留页面供检查，关闭浏览器或停止任务后释放槽位。
npm run add:account -- --company "公司完整名称" --name "张三" --email "name@example.com" --submit
不加 --submit 仅填写表单；--dry-run-parse 仅检查输入，不打开后台。

组合流程
网页点击“网络加速 + 流量规则”：先填写客户资料（公司名称、加速地区和带宽），在“流量规则”中勾选需要的规则，再点击组合按钮。
流程依次创建网络加速、核对本次新建的待开通卡片、提取 ID、自动填入“网络加速服务 ID”，然后进入同一公司后台添加选中规则；此组合无需 IP 参数。
服务 ID 和公司以本次成功的网络加速结果为准，不使用输入框里残留的旧 ID 或其他公司；输入框已被手动修改时保留人工值，本次实际服务 ID 可在日志中查看。
规则添加失败时，先查看日志及已创建的服务，使用“添加选中规则”处理该服务，避免重新运行组合按钮重复购买。
网页点击“完成开通、合约与规则”后，会依次执行“网络加速”、“添加规则”和“开通合约”。
组合流程会在内部自动传递后续任务必需的服务 ID，不再把“获取 ID”显示成独立步骤。
组合步骤串行使用一个浏览器槽位，自动恢复并复用管理员登录态。
服务 ID 会完整匹配，同时校验待开通状态、带宽和选定位置；多个新服务无法确定唯一 ID、结果缺失或公司不匹配时会停止后续步骤并报错。
ID 识别读取完整服务卡片（包含顶部状态和地区），优先检查创建后已显示的卡片；列表延迟加载时轮询等待，并间隔刷新。
未匹配时日志会列出各卡片的 ID 和排除原因，例如创建前已存在、状态未识别、带宽或位置不符；超时后不要重复创建，应核对已生成的服务并补加规则。
自动流程中 Magic 配置填写或保存失败会中断任务，可从网页或生成的配置文件手动处理。

添加规则
npm run rules:add -- --company "公司名称" --service-id 8685 --rules '["office365","TikTok跨境电商"]'
也可用 --file examples/customer.txt 代替 --company，从客户资料读取公司名称。
添加规则会先在管理员用户列表精确查找公司，点击“进入用户后台”并确认，再在该公司后台跳转到服务 ID 对应的规则页。
规则页使用：https://console.osase.net/manage/saas/8685/detail/rules?saas_rule_type=2&page=1&page_size=100&rule_page_2=1&rule_page_size_2=100
其中 8685 会替换为填写的服务 ID，不需要手工拼接链接。
网页“流量规则”的公司名称可单独填写，留空时从上方客户资料读取；组合流程自动沿用网络加速客户的公司名称。
规则处理完成或失败后会恢复管理员登录态，以便后续合约任务继续执行。

完善规程
网页“完善规程”只需填写公司名称，留空时从上方客户资料读取，不需要服务 ID。
规则按钮及勾选状态与“流量规则”共用，包括已保存的谷歌、TK、社媒等自定义组合；在“管理规则按钮”中统一编辑。
点击“完善规程”后，脚本进入管理员“隐藏规则包设置”，打开“添加企业隐藏规则包”，精确选择公司并填写所选规则，然后自动点击“添加”并确认成功。
支持按规则包后台名称、客户展示名称或完整下拉名称匹配，例如 office365 对应“抖音规则包 (office365)”、GL 对应“Google (GL)”。
公司或规则找不到、有多个同名候选、添加失败或未确认成功时会停止并报错，保留浏览器页面供你检查。
npm run rules:complete -- --company "公司名称" --rules '["Google","Google 登录","office365","TikTok跨境电商"]'
也可用 --file examples/customer.txt 读取公司名称；加 --dry-run-parse 可仅检查参数。
